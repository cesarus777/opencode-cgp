## Pinned-host limitations and harness corrections

OpenCode 2.0.29 normalizes away unknown RPC input properties before calling plugin handlers. A raw history request with an extra `path` property returns the same data as the valid request, even though direct handler tests reject extra properties. The supplied path is ignored and never used. Bounds, types and ownership still apply. Strict rejection of every extra wire property cannot be claimed on this host.

Initial harness attempts exposed readiness and forwarding issues: plugin activation follows listener startup; restart log discovery must clear stale listener output; Bun 1.1.34 proxy forwarding requires an explicit POST body and removal of stale response compression/length headers after decompression. These were corrected in the validation harness. The TUI initially reported history unavailable through that broken proxy; corrected forwarding produced actual chart data. No plugin lifecycle change was needed for these harness issues.

The packed suite passed once in full before extending the host fixture. A subsequent run passed all newly added actual-host RPC checks and 11 installed adapter tests, then hit the existing 180-second renderer-dependency installation timeout (exit 137). That attempt is not a full-suite pass. A complete retry with the extended fixture passed: all three actual-host RPCs in both modes, 11 installed adapter tests, CLI report generation, packed native renderer and consumer declarations.

The first synthetic compaction responder returned unstructured text. Native compaction emitted `compaction.failed`, and `test:live` correctly failed despite eventual execution success. The pinned [native summarizer](https://github.com/anomalyco/opencode/blob/4397ee44d038a5f17bf6ac161431673d93e563b5/packages/core/src/session/compaction.ts) requires recognized summary headings. The fixture now recognizes the summarizer request and emits structured text without tool calls; `test:live` then passed with completed compaction and continuation. This was a synthetic-provider fixture correction, not a plugin change.
